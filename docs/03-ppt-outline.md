### P2 痛点与背景

- 员工查制度难：文档散、版本多、找不到（HR/行政高频工单）
- AI 问答落地三大拦路虎：  
  ① 大模型幻觉——编造制度条款风险不可接受  
  ② 内外知识混淆——内部制度与网络信息无法区分权威性  
  ③ 知识不沉淀——同一个问题反复检索，回答质量不收敛
- 讲稿：用"员工问报销标准，AI 给了个网上的错误答案"引入合规风险

### P4 核心创新 ①：LLM-Wiki 知识沉淀引擎

- 问答完成 → 自动抽取结构化知识条目（JSON Schema 展示）
- 待审核 → 管理员审核 → 已生效 → **优先参与检索**
- 价值：回答越问越准、检索越来越快、知识资产持续累积
- 演示：现场走一遍案例 4 闭环（约 60 秒）

### P5 核心创新 ②：内外双源知识隔离

- 内部私有库（制度 PDF/Word）与外部公开库（网页采集）**物理隔离**
- 检索路由隔离：scope 严格路由，代码层面不可达
- 展示：来源标签双色设计（🔒 内部蓝 / 🌐 外部橙）
- 演示：案例 5 隔离验证（切换检索范围）

### P6 核心创新 ③：强制溯源与合规设计

- 硬性四条（对应上架合规要求）：  
  ① 每条回答必须携带来源溯源  
  ② 外部信息强制提示"仅供参考，不作为企业内部制度依据"  
  ③ 无匹配知识回复"暂无相关制度或公开资料"，禁止编造  
  ④ 内外数据严格隔离

### P12 技术难点与解决

| 难点               | 我们的解决                                   |
| ---------------- | --------------------------------------- |
| 大模型幻觉            | 检索强约束 Prompt + 无匹配兜底 + 溯源强制             |
| 知识质量随问答劣化        | Wiki 候选默认待审核，管理员审核后生效                   |
| 内外数据混淆风险         | 双库物理实例隔离 + scope 路由隔离 + 类型标注            |
| 比赛环境不确定（无网/无Key） | MOCK 降级链路 + 前端演示模式 + 种子数据               |
| 短查询召回率低          | 2-gram TF-IDF + 重叠分块 + 阈值调优（冒烟测试 14/14） |

## 答辩问答预演（Q\&A 备战）

**Q：知识条目抽取错了怎么办？**  
A：默认待审核不参与检索，管理员可编辑后生效或直接驳回/删除；抽取内容始终带原文溯源，审核时可直接对照。

**Q：内部文档会不会泄漏到外部？**  
A：双库是两个独立存储实例，外部采集只写外部库；检索按 scope 路由，"仅外部"模式下内部库代码路径不可达。生产版将叠加权限体系与审计日志。

**Q：为什么不用向量数据库/embedding 模型？**  
A：比赛环境不可控（无网/无GPU），TF-IDF 零依赖离线可跑且中文友好；检索接口与向量库同构（add/search），生产化只替换 vector_store 一个文件。

**Q：如何保证大模型不编造？**  
A：三重防线——生成 Prompt 强约束"仅依据资料回答"；无匹配直接走兜底话术不经模型；输出必须携带来源卡片，无来源的回答在前端不展示。

**Q：外部采集的法律风险？**  
A：三道闸（robots/登录墙/清洗）只采公开可访问内容；回答引用外部信息时强制提示"仅供参考"；生产版建议叠加内容版权过滤与白名单域名策略。
