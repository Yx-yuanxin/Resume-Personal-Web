先从已采集事实形成问题假设，再约定业务结果、范围、失败控制和验收。缺少的来源标记待补，不能把六人访谈完整率当作四来源收敛或需求确认。

### 业务流程拆解

要回答：问题发生在哪一步，为什么要这样划分智能体？

1. 先画人工现状泳道，写出触发、输入、8–15个处理步骤、交接和异常。
2. 区分判断点与执行点；按使用的数据、权限、模型能力与失败方式组合执行步骤。
3. 在不可逆动作前设置确定性校验；为低置信、缺资料、冲突和越权安排具名人工接收人。

交付链：现状流程 → 失败方式 → 智能体/工具边界 → 校验与人工升级路径

原文：frameworks/workflow-decomposition.md

### 业务结果与不可逆风险矩阵

要回答：多个需求中，先做哪个最小可验证方案？

1. 列出3–5个候选切入点，分别说明改善的业务结果、现状基线和投入。
2. 评估失败何时被谁看见、能否在损害前拦截、是否可以撤销；不要把模型置信度等同于业务风险。
3. 优先选择高价值、可拦截且可恢复的切入点；高风险需硬约束和责任人否决权，价值或风险未知先补证据。

交付链：候选方案 → 价值/风险比较 → 选择与暂缓理由 → 验收指标与停止条件

原文：frameworks/outcome-risk-matrix.md

### 四来源收敛

要回答：谁说要做，哪里真的坏了，范围允许什么，技术是否可行？

1. Buyer：核实业务目标、预算、优先级和决定权；Operator：用最近一单还原真实操作和失败位置。
2. Brief：核对书面目标、范围、时间和排除项；Industry：寻找可比技术实践，并核实本项目的数据与接口差异。
3. 检查四个视角是否指向同一瓶颈。分歧保留在问题清单：一线帮助定位故障，决策者确认价值，Brief约束范围，行业证据帮助判断可行性。

交付链：四视角陈述与来源 → 收敛/分歧 → 待核实问题 → 有边界的需求假设

### 从证据到候选需求

- REQ-1 支持需求识别环节是首要瓶颈，需先量化各节点等待时间再定AI介入点
  依据：education-support-f00、education-support-f01、education-support-f10、education-support-f20
  推导：流程已定义但管理层未分别量出各节点等待与处理时间（f01、f20），而首次响应26小时对目标8小时差距大（f00），一线又反映连续求助易漏（f10）。因此瓶颈可能位于识别与首次联系之间，但缺少分节点计时数据，无法确认是识别慢还是联系排队。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：抽取两个班级近四周求助样本，按流程六节点逐笔记录进入与离开时间，计算各节点等待中位数与漏单分布；由顾明岚确认口径后再判断AI优先介入识别还是分派。
- REQ-2 交接“假完成”是重复求助与投诉的隐性来源，需以接手确认作为完成标准
  依据：education-support-f23、education-support-f25、education-support-f51、education-support-f54
  推导：交接要求对方确认接手才算完成、仅发消息不算（f23），异常需明确下一责任人（f25）；讲师侧明确不能用发送通知数量代替实际完成量（f51），并指出假完成最易变投诉（f54）。重复求助率35%可能部分源于交接断点，但尚无交接等待与重新联系次数的实测数据。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：在试点前先采集两周交接等待时长与重新联系次数基线，按业务编号核对“已通知未接手”比例；由唐映秋与叶书确认统计口径，作为漏单低于2%验收的补充观察项。
- REQ-3 便签与群聊中的关键说明未随单据流转，需设计可暂存且可追溯的补录机制
  依据：education-support-f14、education-support-f10、education-support-f13、education-support-f45
  推导：关键说明常留在个人便签或群聊、事后补录且不随单据交接（f14），原因是求助散落且现场节奏快（f10）；高峰期只能用现有终端、离开现场补录会延误，草稿需可暂存并标明最后同步时间（f13）。这既造成信息断点，也影响审计可重建（f45），但暂存时长与同步失败提示口径未定。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：先访谈助教确认暂存与同步的现场要求，再以历史资料回放方式验证“暂存—补录—交接”链路是否保留原记录与时间戳；由秦芮确认终端与同步能力，唐映秋确认补录责任归属。
- REQ-4 数据口径未统一前不宜生成支持建议，应先完成主编号与版本校验
  依据：education-support-f31、education-support-f33、education-support-f30、education-support-f35、education-support-f40
  推导：学习活跃度不等于理解、补交与撤回缺统一编号（f31），需先校验主编号、事件时间与版本，歧义记录进人工修复队列（f33）；多系统权限独立、无统一状态视图（f30），接口中断只能用只读快照（f35）。建议必须附实际行为证据（f40），否则存在不可逆的误判风险。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：先对四类资料做一次主编号与版本完整性抽样核验，统计歧义记录比例；由傅景确认可进入建议样本的门槛，未达标前仅做识别与分派提示，不生成支持建议。
- REQ-5 AI在分派环节宜只做提示、由运营员确认，避免责任归属模糊
  依据：education-support-f22、education-support-f25、education-support-f24
  推导：运营员可整理、校核和发起复核，但不能代替数据专员签核或越界操作（f22）；异常先由运营员分派、超时升级主任（f25），规则冲突需附两版本给数据专员（f24）。助教侧也倾向AI只提示未接手、由人确认分派。但“约定时限”具体数值与计时口径尚未核实。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：访谈顾明岚确认分派时限与升级路径，再以回放方式测试“未接手提示”的准确率与误报；验收以运营员确认分派为完成，不由系统自动指派。
- REQ-6 试点指标需固定分母、排除规则与统计周期，否则漏单率与响应时长不可比
  依据：education-support-f53、education-support-f55、education-support-f43、education-support-f02
  推导：各岗统计口径不同（登录率、掌握情况、求助解决率），需分别记录完成时间并固定分母与周期，不能拆分业务抬高比例（f53）；反馈每周收集误判例子、先复测漏单低于2%再更新规则（f55）；留存90天为暂定、真实期限待组织规则确定（f43）。指标口径未定会使验收结论失真。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：由叶书起草指标口径草案（分母、排除规则、周期），顾明岚确认后用于两个班级试点；先做一轮历史数据回算，检验口径是否可复现，再进入并行试点。
