基于自己的课程笔记：检索、问答、出复习卷

大家好，我做的是路径 A 智能体应用：期末复习助手。它只基于自己的课程笔记来检索、回答和出复习卷。

问题与用户

😣 痛点

  • 笔记分散在多个文件里，复习时找不到
  • 自己出题太费时间
  • 网上的题和自己课上学的对不上
  • 通用 AI 会"自由发挥"，编出课上没讲的内容

🎯 用户与目标

  • 用户：正在期末复习的大学生
  • 输入：自己的课程笔记（.md / .txt）
  • 输出：带出处的回答 + 可打印的 HTML 复习卷
  • 原则：只依据笔记，检索不到就如实说没有
痛点有四个，最关键的是最后一条：通用大模型会编。所以我的设计原则是只依据笔记，查不到就如实说。

界面是 Streamlit。核心是 LangChain 1.x 的 create_agent，跑的是 ReAct 循环：模型决定调哪个工具，拿到结果再决定下一步。右边四类能力：模型、本地工具、自己写的 MCP 服务、Skill。

一次完整的调用链：出复习卷

用户："帮我出一份《树与二叉树》的复习卷并导出"

  1. load_skill("exam-review")：加载出卷流程和固定的卷面结构
  2. search_notes("二叉树")：通过 MCP 找到相关笔记
  3. read_note("02_树与二叉树.md")：读取全文，基于全文出题
  4. save_review_sheet(title, markdown)：Markdown 转 HTML，保存到 output/
  5. 回复用户：文件路径 + 卷子结构说明，界面提供下载按钮
这是最完整的一条链路，四个工具依次调用。顺序不是我写死的，是模型根据系统提示词和 Skill 自己决定的。

关键能力 ①：自定义工具 + MCP

本地工具（@tool）

  • exam_countdown：用系统时间算天数，并给出复习节奏建议；不让模型心算
  • save_review_sheet：Markdown → HTML；过滤 Windows 文件名中的非法字符，加时间戳防止覆盖

MCP 服务（FastMCP）

  • 笔记检索做成独立服务，其他 MCP 客户端也能复用
  • 通过 langchain-mcp-adapters 接入，一轮对话共用一个 session
  • 安全：read_note 会校验路径，拦截 ../.env
本地工具两个。MCP 部分我自己写了服务端，不只是调用现成的服务。讲一下安全：如果模型被诱导去读 ../.env，路径校验会直接拒绝。

关键能力 ②：Skill 按需加载

系统提示词里只放技能的一行简介：

可用技能：
- exam-review：根据课程笔记生成期末复习卷……

模型判断需要时，才调用 load_skill 读取正文：

---
name: exam-review
description: ……
---
# 复习卷生成流程
第 1 步：确认范围 → 第 2 步：检索笔记 → ……

好处

  • 节省上下文：不出卷时，完整流程不占 token
  • 易扩展：新技能 = 新建一个 SKILL.md，代码不用改
  • 流程可控：卷面结构、出题规则写在 Skill 里，不靠模型临场发挥
这是我觉得最有意思的设计：渐进式加载。系统提示词里只有一行简介，真正的流程在需要时才加载进来。

关键能力 ③：多轮对话 + 过程可视化

  • Streamlit 用 session_state 保存多轮历史，支持"把刚才那份改成 8 道题"
  • 每一步实时展示：💭 思考 → 🔧 调用工具（参数）→ 📄 返回结果
  • 历史消息可以展开回看工具调用过程；导出的复习卷可以一键下载
  • 出错时显示真实原因（如"未找到 DEEPSEEK_API_KEY"），而不是一大串异常
可观察性很重要：评委和用户都能看到 Agent 每一步做了什么，不是黑盒。

我的项目主要参考 demo_5。模型接入和 MCP 的接入方式是沿用的；Skill 的按需加载，demo_5 是 Deep Agents 框架自带的，我在普通的 create_agent 上用一个 load_skill 工具自己实现了同样的机制。异步这块，demo_5 用常驻后台事件循环，我遇到过第二轮报 Event loop is closed 的问题，最后的做法是每轮新建 HTTP 客户端，让它和事件循环同生共死。

思政与合规

📄 数据来源

示例笔记为 AI 生成、经本人校对，README 中已注明；使用时换成自己的笔记

©️ 版权

只处理用户自己的笔记，不抓取、不传播他人的课件和教材

🎓 使用边界

辅助复习，不替代学习；不编造笔记内容；不用于考试作弊

四个方面。特别说明隐私：笔记片段会发到 DeepSeek 的服务器，这一点要如实告诉用户。

不足与改进

当前不足

  • 关键词检索，近义词可能搜不到
  • 只支持 .md / .txt
  • 每轮对话都要重启一次 MCP 子进程（约 1 秒）
  • 历史只存在浏览器会话中，刷新后丢失

改进方向

  • 加入向量检索（RAG），支持语义搜索
  • 支持 PDF / Word 笔记
  • 参考 demo_5，用 SQLite 检查点保存会话历史
  • 记录错题，根据错题出下一份卷子
